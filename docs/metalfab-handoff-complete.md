## 2. Transport and protocol

- USB CDC serial. Vendor client accepts `1a86:7523` (CH340) and `28e9:018a` (GD32 CDC ACM).
- Default baud **230400**; client connect timeout 3 s, command timeout 10 s.
- Only one device enumerates: GD32 at `/dev/cu.usbmodem3770DAA904B61`. A live probe on 2026-11-17
  confirmed it is the **machine board** (M99 and M808 both answered). Which physical connector that
  is remains unconfirmed (see 6.1).

**Line protocol.** `M<number>` plus optional ` <letter><value>` parameters, LF-terminated. The
board echoes the command prefix; a client matches the echo and reads the remainder. Parameter
parsing is centralised in `FUN_08016bb2(buf, len, index, letter, out)`; values parse as floats and
are converted with `VectorFloatToUnsigned` where the handler wants an integer. Missing or negative
float parameters fall back to `-1.0` sentinels.

**f0f7 protocol** (upgrade only, client-side layout):

```
packet    = [0xF0] [body] [checksum] [0xF7]
body      = prefix_bytes + command_bytes + LF
checksum  = (sum(body_bytes) & 0x7F)
verifyLen = 1 + len(body)      # how many leading response bytes must echo the request;
                               # NOT transmitted
```

Per-board `verifyLength` values (`[2048,128]`, `[0,2]`) are **unresolved** — see 6.3.

### 3.2 Status report — `M808` (`data/status.json`)

`FUN_0801ef70` prints `M808` then calls builder `FUN_0801bb9c`. Output order:

1. `--- Laser Ruike Status Report ---`
2. `--- Device Status (STA) ---`
3. Device fields
4. `--- Raycus Status (STR) ---`
5. Raycus fields
6. `=== End of Status Report ===`

**Device (STA)** — raw status `+0x50`; Temperature Status `+0xcf` (with low flag `+0xda`); Laser
Status `+0xd0`; External AD `+0xd1`; Fault Status `+0xd2`; Red Light `+0xd3`; MOD `+0xd4`; GATE Mode
`+0xd5`; External Control `+0xd6`; Ready Status `+0xd7`; Laser Emission `+0xd8`; WAVE Mode `+0xd9`;
Red Light Control `+0xdb`; Severe Fault `+0xdc`.

**Raycus (STR)** — raw status `+0x54`; ACDC `+0xde`; Driver 1–4 `+0xdf`–`+0xe2`; Emission `+0xe3`;
Scattered Light 1 `+0xe4`; Power `+0xe5`; Interlock 1 `+0xe6`; Interlock 2 `+0xe7`; Interlock Error
`+0xe8`; Raycus Ready `+0xe9`; Laser Lock `+0xea`.

Status struct base is RAM `0x2002085c` (pointer stored at `0x0801be58`). Value strings: `ON`
`0x0801bee4`, `OFF` `0x0801bee8`, `Yes` `0x0801bff0`, `No` `0x0801bff4`, `Closed` `0x0801c0e4`,
`Open` `0x0801c0ec`.

The later audit traced both `Raw Status Value` parsers and confirmed 25 bit-to-field associations.
See the table in `docs/protocol-notes.md` §6.

### 3.4 Settings and persistence

Settings live in the RAM struct returned by `FUN_0800a424()`. Setter clamp bounds are at `+0x100`/
`+0x104` (M800), `+0xc0`/`+0xc4` (M801), `+0x1e0`/`+0x1e4` (M802) and are populated at runtime from
config, not compile-time constants. Configuration persists to flash as JSON with defaults for
`first_usage`, `language`, `imperial_units`, `scan_width_correction`, `origin_correction`,
`protective_mirror_temp_threshold`, `gas_pressure_min`, `gas_pressure_max`, `focus_correction`,
`focus_set_status`, `red_laser_set_status`, `wide_cleaning_working_flag`, `origin_correction_power`.

### 3.6 Screen image

`55 AA` container: header, named entries (`3:/bin`, `3:/bin/image.bin`), then **19 zlib streams**
starting at offset 62. Three inflate to exactly 1,572,864 bytes (SPI-flash images); sixteen inflate
to 54–150 KB asset blobs. After the streams (offset `0x1258e`) come **raw PNG assets**, and the file
ends with ASCII model data.

The uncompressed `3:/bin/screen.bin` page bundle contains multilingual UTF-8 UI strings. The
machine firmware selects the page, including for the wire-feeding alert. See
`docs/protocol-notes.md` under **Wire-feeding alert mapping** for the event and page IDs.

### 3.7 Bootloader and heartbeat

- `M222 S6` only **acknowledges**. The F0F7 bootloader is not in the distributed application
  image, so device-side ACK/NAK opcodes and `verifyLength` semantics cannot be recovered here.
- Heartbeat strings (`0x0802572b`, `0x0802575c`) occur near `M99\n`. The route and cadence
  remain unverified. Receive-only traces contain asynchronous events.

### 3.8 Live probe (2026-11-17)

Probe of `/dev/cu.usbmodem3770DAA904B61` at 230400, exclusive, DTR/RTS off. No writes beyond
`danger: none` getters.

**M99 is a per-board version query, four lines (app + bootloader):**

```
M99 A40.71.003.2425.01.B04 B40.71.001.2425.00.B01
M99 A40.71.003.2540.01.B03
M99 A40.71.001.2622.01.B01 B40.71.001.2622.00.B01
M99 A40.70.005.2722.01.B02 B40.70.001.2722.00.B01
```

The installed welding head is `40.70.005.2722.01.B02` while the firmware folder ships
`40.70.006.2722.01.B01` — the machine is one revision behind on the head. Screen and machine match
the folder.

**M808 full report:** every field `Normal` / `Disabled` / `OFF`; both `Raw Status Value` words
`0x00000000`; `Interlock 1: Open`, `Interlock 2: Open`, `Laser Lock: Unlocked`, `Ready Status: Not
Ready`. The builder output matches `data/status.json` exactly, including header order and terminator.

**Getter values observed:** `M817 A30` (NTC 30 °C), `M812 A1`, `M818 A3440 B3007 C256 D324 E1859 H1`,
`M810 A5`, `M811 A1 B0 C1 D1 E1`, `M845 A451 B0`, `M864 A3`, `M865 A0`, `M839 A800`.

**Critical framing finding:** responses interleave unsolicited lines — file-manager logs
(`Folder 'continus' for mode 0 contains 0 files.`, `Failed to open index file: -2`,
`No files found in machining mode 'continus'.`) and sub-board echoes (`M870 A0`, `M871 A12.00`,
`M879 A200`, ...). This is direct confirmation of the event-queue requirement: echo-prefix matching
completes the outstanding request; every other line must be surfaced as an event and never dropped.

`M857` in particular returns a burst of current settings (`M800 A50`/`A60`, `M801 A2.0`/`A1.8`,
`M871 A12.00`, `M873 A15.00`, `M875 A12.00`, `M879 A200`, `M887 A0`/`A150`), which is a useful
live sanity check for the settings layer.

## 2026-11-17 (later) — E-stop and trigger capture

Ran a 1 Hz `M808` capture while physically changing states on the machine. Transitions observed
(timestamps relative to capture start):

- **91.42 s — emergency stop pressed:** `Stop Swtich Abnormal`, `RGB_LAMP: color = 2, on_time = 500,
  off_time = 0, total_times = 65535`, `BUZZER: freq = 4000, on_time = 500, off_time = 500,
  total_times = 3`, `M850 C0`, `M806 A0 B500 C0 D65535`.
- **108.6–109.1 s — emergency stop released:** `Stop Swtich Normal`, `M850 C1` (twice, debounce).
- **111.76 s:** `AC Touch Normal`.
- **123.66 s:** `Laser Fault Normal`.
- **Trigger pull with laser disabled:** produced no output.

**Conclusions that change the model:**

1. All 26 named fields and both `Raw Status Value` words stayed at their idle values during
   the recorded stop-switch transitions. Asynchronous `Stop Swtich Abnormal/Normal` lines
   identified the transitions.
2. The raw words stayed at zero during this observation. A later firmware audit traced
   both source parsers and recovered bit-to-field associations in `docs/protocol-notes.md` §6.
3. New unsolicited line types for the event queue: `RGB_LAMP: …`, `BUZZER: …`, `M806 A0 B500 C0
   D65535` (screen command), and `M850 C0`/`M850 C1` (laser sub-board interlock toggle). Treat all of
   them as events, not responses.
4. `AC Touch Normal` and `Laser Fault Normal` appear as periodic/latent announcements rather than
   replies to anything we sent.
